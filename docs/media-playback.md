## What changes

`proprietary_codecs = true` registers H.264 and AAC with Chromium's MIME/media pipeline. `ffmpeg_branding = "Chrome"` selects the FFmpeg decoder configuration that includes H.264/AAC on Android ARM64 and x64. This is FFmpeg flavor, not Google product branding. Existing Android MediaCodec, software fallback, site permissions, controls, sandboxing and profile policies remain upstream behavior.

Pinned upstream defaults derive HLS, MPEG-2 TS parsing and platform HEVC from proprietary codecs. VP8/VP9, Opus and AV1 remain available in the configuration. Actual HEVC and hardware acceleration depend on platform decoders; no forced hardware or vendor codec flags are added.

`scripts/archium-media-preflight.py` inspects effective GN arguments after generation and before compilation. Missing, malformed, disabled or mismatched values stop the build. Its JSON output explicitly marks playback, hardware decoding and premium DRM unverified. A compiled-in format is not proof of playback.

## Local configuration checks

```sh
ARCHIUM_TEST_GN=/path/to/pinned/gn python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/check-arc-preparation.py --android-jar /opt/android-sdk/platforms/android-37.0/android.jar
bash -n scripts/build-archium.sh
```

The JS evidence checker can be run with `node tests/runtime/media/media-tests.test.cjs`; eight assertions exercise time advancement, fresh frames and error rejection. This is not browser playback.

The pinned-GNI tests require real GN. With no GN they are visibly skipped; set `ARCHIUM_TEST_GN` to run them. The project supplies unmodified pinned files with hashes. They run in a synthetic non-media Android platform context and do not establish full Chromium GN/build success.

## Googlebook Intel preparation

```sh
python3 scripts/archium-build-config.py --target-cpu x64 --output /path/to/chromium/src/out/Archium-x64/args.gn
# In the complete patched Chromium checkout:
gn gen out/Archium-x64
python3 /path/to/repo/scripts/archium-media-preflight.py --out "$PWD/out/Archium-x64"
autoninja -C out/Archium-x64 chrome_public_apk
```

ARM64 configuration is generated with `--target-cpu arm64`; it remains the default. Only arm64/x64 are accepted. This prepares configuration, not a verified Intel APK. The staged GitHub workflow and artifact naming still target ARM64. Do not label that APK as x64 or assume ARM checkpoint objects can substitute for an Intel rebuild.

## Runtime acceptance

The committed corpus is nine tiny owned pattern/tone files, approximately 0.5 MB. `scripts/generate-media-fixtures.py` regenerates them and records stream metadata, sizes and SHA256s using FFmpeg/ffprobe; generated bytes may differ across encoder versions.

```sh
python3 scripts/serve-media-tests.py --port 8765
adb -s emulator-5554 reverse tcp:8765 tcp:8765
# Open http://127.0.0.1:8765/ in the actual media-enabled Archium APK.
# Press "Ejecutar 8 pruebas"; then save the JSON report.
```

The server binds localhost, supplies bounded/suffix/open byte ranges for seeking and rejects links outside the fixture directory. Stop it with Ctrl+C and remove only the reverse mapping you created with `adb -s emulator-5554 reverse --remove tcp:8765`.

Eight automated cases cover MP4/H.264/AAC, AAC-only, VP8/Opus, VP9/Opus, AV1/Opus, seeking, fragmented MP4 via MSE, and native clear HLS. Each requires real time advancement and, for video, additional decoded/presented frames. Capability advertisements do not pass a playback case. Errors/timeouts are recorded; listeners, media sources and object URLs are released between cases.

Record the installed package, APK SHA and source commit externally: JavaScript cannot authenticate that it is executing in Archium. Running in another browser only validates the harness. Audio tests are muted for automation; audible audio, fullscreen, PiP, resizing and hardware decode require device checks. The page restores an unmuted, paused H.264/AAC sample for manual checks.

MSE verifies streaming foundations, not every DASH service. Native HLS remains an APK acceptance test, not a promise that every playlist works. Widevine already defaults to Android's MediaDrm route in this revision; no CDM downloads, security-level spoofing, license bypass or premium-service certification is added.
