Wrapped activity contexts reuse the existing visualContext resolver. No control styling/dimensions changed.
- kAndroidMediaPicker and kUserMediaScreenCapturing are enabled by default, retaining explicit feature disable mechanisms. ENABLE_SCREEN_CAPTURE is already true at this exact pin. The pinned fieldtrial_testing_config.json contains neither an AndroidMediaCapture study nor AndroidMediaPicker/UserMediaScreenCapturing experiments; this is not assumed to match another Chromium branch.
- ServiceLoaderUtil is still preferred when a picker implementation exists. The new fallback uses the existing headless fragment and **zero-argument createScreenCaptureIntent()**, preserving One UI's phone/external-display/application choice and passing its unmodified one-use result into ScreenCapture.onPick then onPickWindow. This code-level cancellation path and disabled defaults explain concrete blockers; they do not prove the cause of every NotAllowedError on the installed APK.
- TYPE_WINDOW and TYPE_SCREEN both use DesktopCapturerAndroid in the pinned content/public/browser/desktop_capture.cc. No Windows/macOS backend is ported. The common DisplayMediaAccessHandler/device/indicator pipeline remains intact. ScreenCapture already registers MediaProjection callbacks before its VirtualDisplay, resizes the surface/display using onCapturedContentResize, observes window changes and releases capture resources. The existing notification service aggregates camera/microphone/mediaProjection foreground types and provides stop controls; the manifest already declares them. No camera/microphone track is stopped or replaced by the integration, and no Companion Mode is selected.
- Public Android results do not disclose whether the selection was a monitor or application. The existing upstream TYPE_WINDOW convention is retained: displaySurface reporting is not evidence of the actual physical display. System audio and isolated browser-tab capture are not implemented by this fallback. Source/enterprise restrictions that cannot safely be enforced by the unrestricted system chooser fail closed; selfBrowserSurface only filters browser tabs, which this chooser does not enumerate.
- Pending consent is cancelled on Activity destruction; late results and a destroyed native request are ignored. A second prompt cannot overwrite the same Activity's pending callback. Launcher failures release the pending slot. Consent is never stored as a permanent site grant.
- Document PiP reuses the real upstream DocumentPictureInPictureActivity/PopupCreatorImpl, including opener-origin checks, same-origin WebContents, native close handling, Android17 pinned layer and display placement. Its Blink runtime capability is set **per document at ReadyToCommit**, after redirects, only for actual Desktop windows on Android17+. The Android global feature default remains unchanged. The app-side disposition handler uses the same eligibility and never falls through to normal tab creation when PiP is rejected. It calls the existing stateless PopupCreatorImpl directly because this pin's low-level factory can be unregistered on phone-class hardware. No participant overlay, SAW permission or fake PiP is added. Automatic entry/Media Session eligibility and dismissal preferences are left to upstream/site behavior, not forced.
