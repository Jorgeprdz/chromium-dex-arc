# Arc for Mac Look and Feel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reproduce Arc for Mac appearance and browser interactions on tablet/desktop Android with an explicit Arc/mobile choice.

**Architecture:** Keep Chromium TabModel, bookmarks, omnibox and native lifecycle. Replace the earlier header-only design with a composed Arc sidebar/frame, persistent local sidebar state and real browser actions; viewport clipping is integrated with the compositor.

**Tech Stack:** Java Android, Chromium native browser controls/tab UI, GN, C++ compositor integration where required.

**Spec:** `docs/superpowers/specs/2026-10-06-archium-local-arc-design.md`.

**Execution:** Inline. Review this plan before implementation.

## Global Constraints

- Chromium revision `cfd94726b7b5fb48aedcc32662f2f3fbdbadec35`.
- Arc for Mac references; `docs/references/arc-mac-pinned-tabs.png` proves only the visible sidebar/header region. Complete references for bottom controls and expanded/collapsed/hover states before matching them.
- Tablet and desktop are eligible without Samsung-only fields; manual Arc choice works on phones.
- Preserve native tab/omnibox/navigation/incognito/extensions. No decorative controls with false behavior.
- Frame theme cannot tint webpages; rounded content must clip for real, never overlay masks.
- No automatic destructive archiving of existing tabs.
- Upstream edits live in `.source-modified/`, exact originals in `.source-reference/`, new upstream files in `chromium/`; regenerate the pinned patch manifest at integration.

## Review Focus

- Tablet without DeX, phone rotated and display reconnect: correct policy and no tab loss.
- Search/selection during lifecycle destruction: no stale callbacks or wrong-profile navigation.
- Closed pinned tab, missing favorite tab and restored sessions: stable local entries and real native tabs.
- Sidebar resizing/collapse and keyboard focus: controls stay reachable without covering webpages.
- Dark/incognito/color extremes: contrast, profile isolation and untinted web content.

### Task 2: Persistent Favorites, pinned entries and local Spaces

**Files:**
- Create: `chrome/android/java/src/org/chromium/chrome/browser/arc/ArcSidebarState.java`.
- Create: `chrome/android/java/src/org/chromium/chrome/browser/arc/ArcSidebarStore.java`.
- Create: `chrome/android/java/src/org/chromium/chrome/browser/arc/ArcTabActions.java`.
- Modify: `ArcDesktopCoordinator.java`, native tab/vertical-tabs integration and `chrome_java_sources.gni`.
- Test: pure state/store tests and native TabModel integration tests.

**Interfaces:**
- `ArcSidebarState` defines versioned persisted Space, Folder, PinnedEntry and Favorite identities. A pinned entry stores canonical URL/title and optional native tab association; favorites are shared between local Spaces.
- `ArcSidebarStore.load(): ArcSidebarState`, `save(ArcSidebarState): void`; persist through Chromium profile preferences with versioned migration, no credentials or web content.
- `ArcTabActions.selectOrOpen(entryId)`, `closeTab(tabId)`, `pin(tabId, spaceId)`, `move(entryId, targetSpaceId, folderId, index)`; adapter to TabModel/TabCreator/bookmark models.

- [ ] Write RED tests: stable entry identity/order after reload; closing pinned tab preserves entry/canonical URL; reopening selects/creates exactly one tab; moving between Spaces/folders preserves identity; normal and incognito state cannot mix; invalid persisted association recovers by reopening.
- [ ] Implement state model, persistence and migrations. Bridge native tab events without representing pinned tabs as a list of unrelated header bookmarks.
- [ ] Wire real local Spaces only if they are shown in the reference; selecting one changes its visible pinned/open collections. No visual dots without function.
- [ ] Run state/native tests. Expected all operations survive restart and no duplicate or lost native tabs.
- [ ] Commit model, adapters and tests.
